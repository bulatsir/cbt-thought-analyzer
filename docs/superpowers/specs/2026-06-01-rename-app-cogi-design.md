# Переименование приложения в «Cogi» — Design

**Дата:** 2026-06-01

## Цель

Переименовать iOS-приложение в **Cogi** (display-имя `Cogi`, мысленно по-русски «Коги») —
короткое, легко произносимое и запоминающееся имя-компаньон с отсылкой к уму/мышлению
(cognition). Меняем пользовательское имя **и** внутренние имена (target/scheme/файлы/struct/
папка репо), но **сохраняем identity приложения** (bundle ID), чтобы сохранённые на устройстве
данные не потерялись.

## Выбор имени

`Cogi / Коги` — мягкая форма «Cogni» (cognition), дружелюбное звучание (рядом с «корги» —
вайб маленького помощника), корень про мышление. Читается одинаково чисто на латинице и
кириллице, 2 слога. Выбрано из финального шорт-листа (Uma, Cogi, Mindo, Nous).

## Зафиксированные решения

| Параметр | Значение |
|---|---|
| Display name (`CFBundleDisplayName`) | `Cogi` |
| Bundle ID | **без изменений** — `com.bulsir.cbtanalyzer` |
| Xcode target + scheme | `CBTAnalyzer` → `Cogi` |
| Entry-point файл/структ | `CBTAnalyzerApp.swift` / `struct CBTAnalyzerApp` → `CogiApp.swift` / `struct CogiApp` |
| Папки исходников | `CBTAnalyzer/CBTAnalyzer/` → `Cogi/Cogi/` |
| Папка репозитория | `~/Projects/abc_app_ios` → `~/Projects/cogi_ios` |
| UserDefaults-ключи `cbt.*` | **НЕ трогаем** (см. ниже) |
| Бэкенд-домен, base URL, репо `abc_app` | **вне scope** |

## Почему bundle ID остаётся прежним

Смена bundle ID = для iOS это новое приложение: старая иконка остаётся отдельно, а
`Documents/entries.json` (включая данные эмоциональных тем, которые сейчас тестируются на
устройстве) **не мигрирует** — импорта в приложении нет. Bundle ID невидим пользователю,
поэтому держим `com.bulsir.cbtanalyzer` и сохраняем все данные + текущий провижининг.

## Почему ключи `cbt.*` остаются прежними

`SettingsStore` и `DeviceID` пишут в `UserDefaults.standard` по строковым ключам с префиксом
`cbt.` (`cbt.language`, ключ Device ID). Эти ключи — обычные строки, **не** завязаны на имя
приложения. Переименование target/struct их не меняет. Если их «заодно» переименовать в
`cogi.*`, при первом запуске после ренейма сбросятся выбранный язык и Device ID (→ новый
rate-limit identity). Поэтому ключи `cbt.*` остаются как есть; это внутренние строки, юзеру
не видны.

## Объём изменений

### iOS-репозиторий (`cogi_ios` после ренейма папки)

1. **Display name** — добавить `INFOPLIST_KEY_CFBundleDisplayName = Cogi` в обе build-конфигурации
   (Debug/Release). Это гарантирует имя «Cogi» на домашнем экране независимо от имени target.
2. **Target + scheme** `CBTAnalyzer` → `Cogi`. Делается в Xcode UI (переименование target атомарно
   тянет scheme, `PRODUCT_NAME = $(TARGET_NAME)` и ссылки на файлы). Ручная правка `project.pbxproj`
   — запасной путь, более хрупкий.
3. **Entry point** — `CBTAnalyzerApp.swift` → `CogiApp.swift`, `struct CBTAnalyzerApp` → `struct CogiApp`.
4. **Папки** — контейнер проекта и группа исходников `CBTAnalyzer/CBTAnalyzer/` → `Cogi/Cogi/`.
5. **Косметика** — заголовочные комментарии `// CBTAnalyzer…` в `.swift` обновить на `// Cogi`.
6. `ContentView.swift` — изменений по существу нет; имя `CBTAnalyzer` в коде встречается только
   как имя entry-struct (п. 3). Ключи `cbt.*` не трогаем.

### Папка репозитория

7. `mv ~/Projects/abc_app_ios ~/Projects/cogi_ios` (git-репозиторий имя папки не хранит — простой
   перенос). Выполнять **до** правок внутри, чтобы дальнейшая работа шла по новому пути.

### Документация / память (репо `abc_app`)

8. Обновить пути `~/Projects/abc_app_ios/` → `~/Projects/cogi_ios/` в `CLAUDE.md` и в memory-файлах,
   которые ссылаются на этот путь (напр. `ios_app_in_progress.md`).
9. Упоминания имени iOS-приложения в `CLAUDE.md` (display-имя) обновить на «Cogi» там, где это про
   само приложение. Концептуальное имя продукта/бэкенда «CBT Thought Analyzer» — оставить (вне scope,
   при желании — отдельный follow-up).

### Вне scope

- Бэкенд-домен `api-abc.bulsir.com`, `baseURL` в клиенте, имя репо `abc_app` — API внутренний,
  юзеру не виден, приложение продолжает ходить на тот же URL.
- App icon — отдельная задача (есть в backlog).

## Порядок выполнения

1. Переименовать папку репо (`mv`).
2. В Xcode: переименовать target → `Cogi` (тянет scheme/PRODUCT_NAME).
3. Переименовать `CBTAnalyzerApp.swift`/`struct` → `CogiApp`; папки `Cogi/Cogi/`; комментарии.
4. Добавить `CFBundleDisplayName = Cogi`.
5. Обновить пути/имя в `CLAUDE.md` + memory.
6. Верификация: сборка на устройстве (делает пользователь), проверить домашний экран = «Cogi»,
   сохранённые entries на месте, язык/Device ID не сбросились.

## Разделение труда

- **Пользователь:** переименование target/scheme в Xcode (атомарно и безопасно), сборка/прогон на
  устройстве.
- **Claude:** `mv` папки репо, переименование Swift-файла/struct/комментариев, добавление
  `CFBundleDisplayName`, правка `CLAUDE.md` + memory, обновление `project.pbxproj` для файловых
  ссылок при необходимости.

## Риски и верификация

- **Потеря данных** — исключена: bundle ID и ключи `cbt.*` неизменны → `entries.json`, язык, Device ID
  сохраняются.
- **Хрупкость `project.pbxproj`** — минимизируется тем, что target/scheme переименовывает Xcode UI.
- **Расхождение путей** — после `mv` все ссылки на `abc_app_ios` в доках/памяти обновляются в одном
  проходе (п. 8).
- XCTest в проекте нет → верификация = сборка пользователем на устройстве + ручная проверка
  (имя на экране, сохранённые данные, язык).
