# Design: few-shot улучшение промпта детекции когнитивных искажений

**Дата:** 2026-05-16
**Файл изменения:** `backend/app/prompts.py` (только `build_system_prompt`)
**Версия бэка:** `cbt-backend:v0.1.9`
**Клиент (iOS):** изменений нет — JSON-контракт не меняется

---

## 1. Проблема

Текущий `build_system_prompt` — голый список 18 искажений + правила, **без единого примера**. Два наблюдаемых дефекта (со слов пользователя):

1. **Ложное срабатывание на не-мысли.** Ввод `усталость` (одно слово, состояние — искажать нечего) → модель отвечает `Катастрофизация`. Текущее правило ловит только явный мусор (`asdf`, `ыыы`), но не осмысленные не-мысли: одиночные слова, чистые эмоции, констатации фактов, **соразмерное реальности беспокойство**.
2. **Слабое объяснение.** Нет требования опираться на текст → `explanation` выходит общей формулой под ярлык. Даже верный ярлык читается как «притянут».

Корень общий: модель не видит образца «когда молчать» и «как объяснять». Лечится few-shot примерами (подход A — выбран пользователем; B «только правила» отклонён как ненадёжный, C «менять контракт» — как ломающий iOS-клиент).

## 2. Что НЕ меняется (границы)

- `backend/app/schemas.py`, `backend/app/groq_client.py`, `backend/app/main.py`, `backend/app/rate_limit.py` — не трогаем.
- JSON-контракт ответа (`{"distortions":[{"name","explanation"}]}`) — неизменен.
- Канонический фильтр в `groq_client.analyze()` (`_CANONICAL_NAMES_BY_LANG`, cap `[:3]`) — работает как есть.
- iOS-клиент (`~/Projects/abc_app_ios/`) — ноль изменений, рендерит `name`/`explanation` как есть.
- Список `DISTORTIONS` / `DISTORTIONS_EN` (18 имён, фиксированный порядок) — неизменен.

## 3. Изменения в `build_system_prompt`

Структура промпта (обе ветки `ru` / `en`): `роль → список 18 → ПРАВИЛА (изменены) → FEW-SHOT (новый блок) → формат ответа (неизменен)`.

### 3.1 Изменённые правила

Заменяем нынешнее узкое правило про мусор на расширенное правило «не-мысль» и добавляем правило цитаты. Остальные правила (0–3 искажения, только из списка, без «пациента», только JSON) — без изменений.

**Правило «не-мысль» (RU-формулировка для промпта):**

> Когнитивное искажение может существовать только внутри **автоматической мысли** — суждения, оценки, интерпретации или прогноза о себе, других людях или будущем. Если ввод не является такой мыслью — верни **пустой массив** `distortions`. Не натягивай искажение на не-мысль. Не-мысль это:
> - одно слово или короткая пометка состояния («усталость», «работа», «тревога»);
> - называние эмоции без оценки («мне грустно», «злюсь», «тревожно перед собеседованием»);
> - нейтральная констатация факта или плана («завтра встреча в три», «идёт дождь», «я не поел»);
> - **соразмерное реальности беспокойство или решение задачи** («мало готовился, могу плохо сдать — сегодня позанимаюсь») — реалистичная, взвешенная мысль не является искажением;
> - вопрос без заложенного убеждения («что приготовить на ужин?»);
> - предпочтение или вкус («я люблю кофе», «не нравится этот фильм»);
> - бессмыслица или тестовый ввод («asdf», «ыыы», «test test»).
>
> Ключевой разделитель: искажение живёт в **оценке**, а не в факте или эмоции. `я не поел` → пусто; `я не поел, потому что я ничтожество, не заслуживающее заботы` → есть искажение.

> **Grounding:** правило опирается на когнитивную модель Бека (ситуация → автоматическая мысль → эмоция) и на разделение колонок «ситуация / чувство / мысль» в *Mind Over Mood* (Greenberger & Padesky): эмоция и факт по определению не являются искажённой мыслью; соразмерная реалистичная мысль — тоже не искажение (КПТ работает только с *искажёнными* оценками).

**Правило цитаты (RU-формулировка для промпта):**

> В `explanation` опирайся на конкретную формулировку из мысли — приведи её (можно близко к тексту, дословность не требуется) и объясни, *почему именно она* делает мысль этим искажением. Не пиши общих фраз вроде «в мысли есть преувеличение» — покажи, какая именно формулировка его создаёт. Объясняй когнитивную операцию **самого этого искажения**: не описывай эмоцию-следствие («…и поэтому обидно/виновато») и не пересказывай механику другого искажения. 1–2 предложения, живым языком, без слов «пациент/клиент/пользователь».

> **Решения по ревью (2026-05-16):** требование *дословной* подстроки-цитаты снято (перефраз, ухватывающий суть, допустим — модель разберётся); правило «один ярлык по умолчанию» НЕ вводится (в реальных мыслях искажения обычно идут пучком). Оставлены только фиксы качества объяснения (см. ниже B1/S5) и EN-гейт (§4).

### 3.2 Few-shot блок

Вставляется между правилами и форматом ответа, с подводкой: *«Примеры (изучи и следуй такому же стилю; формат ответа — строго JSON как ниже):»*. Каждый пример — пара `Ввод: …` → `Ответ: {json}`.

EN-ветка — **зеркало**: те же входы переведены на английский, `name` берётся из `DISTORTIONS_EN` (тот же индекс), `explanation` на английском с цитатой английской фразы. Канонические имена строго из соответствующего языкового кортежа.

Покрытие: все 18 искажений показаны минимум один раз; 4 путаемые пары из исследования разведены контрастными соседними примерами.

#### Негативные примеры (5) — учат сдержанности

| # | Ввод | Ответ | Чему учит |
|---|---|---|---|
| N1 | `усталость` | `{"distortions":[]}` | одно слово / состояние (регресс-кейс реального бага) |
| N2 | `мне тревожно перед собеседованием` | `{"distortions":[]}` | чистая эмоция + факт, нет оценки |
| N3 | `мало готовился, могу плохо сдать экзамен — сегодня позанимаюсь` | `{"distortions":[]}` | **соразмерное реальности** + решение (ключевой класс над-срабатывания) |
| N4 | `завтра встреча в три часа` | `{"distortions":[]}` | нейтральный факт / план |
| N5 | `asdf` | `{"distortions":[]}` | мусор / тест |

#### Позитивные примеры (17) — учат стилю объяснения + разводят путаемые пары

Каждый `explanation` ниже — финальный текст для промпта (RU). Формат: «цитата» + механика искажения.

| # | Ввод | name(s) | explanation |
|---|---|---|---|
| P1 | `я завалил собеседование, меня теперь вообще никуда не возьмут` | Сверхобобщение; Поспешные выводы: предсказание будущего | «Слово „никуда“ раздувает один отказ до бесконечного паттерна, а „не возьмут“ подаёт ещё не случившееся будущее как уже решённый факт.» |
| P2 | `он не поздоровался — наверное, считает меня никчёмным` | Поспешные выводы: чтение мыслей | «„Считает меня никчёмным“ — это приписывание чужих мыслей без проверки: молчание истолковано как доказательство негативного отношения.» |
| P3 | `я полное ничтожество` | Навешивание ярлыков | «„Полное ничтожество“ — фиксированный ярлык на всю личность вместо описания конкретной ситуации; человек приравнивается к одной оценке.» |
| P4 | `если сделано не идеально — лучше вообще не делать` | Перфекционизм | «Планка „идеально“ задаёт недостижимый стандарт, при котором любой результат ниже совершенства обесценивается до бессмысленного.» |
| P5 | `либо всё получилось, либо это полный провал` | Чёрно-белое мышление | «„Либо… либо… полный провал“ — только две крайние корзины без промежуточных оценок; середина исключена.» |
| P6 | `мне сделали одно замечание, и теперь весь день испорчен` | Ментальный фильтр | «Одна деталь — „одно замечание“ — заслоняет весь день: внимание застряло на единственном негативе, остальное не учитывается.» |
| P7 | `в этой работе вообще нет ничего хорошего` | Туннельное зрение | «„Вообще ничего хорошего“ — обзор сужен до одной негативной стороны, любые плюсы заранее не попадают в поле зрения.» |
| P8 | `меня похвалили просто из вежливости, это не считается` | Обесценивание положительного | «„Это не считается“ активно аннулирует реальную похвалу, объясняя её вежливостью, — положительное переводится в ноль.» |
| P9 | `да, я пробежал марафон, но это ерунда, любой может` | Минимизация | «Достижение признаётся, но „ерунда, любой может“ сжимает его до незначительного — масштаб собственного результата занижен.» |
| P10 | `мне страшно — значит, точно случится что-то плохое` | Эмоциональное обоснование | «Связка „страшно — значит случится“ выводит факт из чувства: эмоция принимается за доказательство реальности.» |
| P11 | `если я ошибусь на работе — меня уволят и всё рухнет` | Катастрофизация; Поспешные выводы: предсказание будущего | «„Всё рухнет“ разгоняет возможную ошибку до предельной катастрофы, а цепочка „ошибусь → уволят“ подаётся как неизбежный прогноз.» |
| P12 | `я никогда не должен ошибаться` | Долженствование | «„Никогда не должен“ — жёсткое абсолютное требование к себе вместо гибкого предпочтения; ошибка превращается из обычного события в недопустимое нарушение правила.» |
| P13 | `команда сорвала срок — это всё из-за меня` | Персонализация | «„Всё из-за меня“ берёт единоличную вину за общий результат, который зависел не только от одного человека.» |
| P14 | `все ровесники добились большего, я на их фоне пустое место` | Сравнение; Навешивание ярлыков | «Мерило „на их фоне“ ставит ценность через сравнение с другими, а „пустое место“ закрепляет это фиксированным ярлыком.» |
| P15 | `это несправедливо: я работаю больше всех, а повысили другого` | Ошибка справедливости | «„Несправедливо“ применяет личный эталон справедливости как объективное мерило мира — ситуация судится по правилу „мир обязан быть честным ко мне“.» |
| P16 | `от меня всё равно ничего не зависит, всё решают другие` | Ошибка контроля | «„Ничего не зависит, всё решают другие“ — позиция полной внешней управляемости, отрицающая собственное влияние.» |
| P17 | `я несчастен только из-за них — это они во всём виноваты` | Обвинение | «„Только из-за них“, „они во всём виноваты“ — ответственность за своё состояние целиком вынесена на других.» |

**Разведённые путаемые пары** (явные контрастные соседи в наборе):
- Ментальный фильтр (P6) ↔ Туннельное зрение (P7): одна деталь vs сужение всего обзора.
- Чтение мыслей (P2) ↔ Предсказание будущего (P1/P11): чужие мысли сейчас vs прогноз будущего.
- Персонализация (P13, вина внутрь) ↔ Обвинение (P17, вина наружу) ↔ Ошибка контроля (P16, общая позиция о власти).
- Чёрно-белое (P5, две корзины без стандарта) ↔ Перфекционизм (P4, недостижимый стандарт) ↔ Долженствование (P12, явное «должен»).
- Обесценивание положительного (P8, «не считается» — в ноль) ↔ Минимизация (P9, «ерунда» — уменьшение).
- Сверхобобщение (P1, паттерн во времени) ↔ Навешивание ярлыков (P3, фиксированная личность).

> Все определения и разделители взяты из: Burns *Feeling Good* (10 классических), McKay/Davis/Fanning *Thoughts and Feelings* «15 styles» (13, 15–18), Beck (когнитивная модель), Greenberger & Padesky *Mind Over Mood* (определение автоматической мысли и негативная таксономия). Полный отчёт исследования — в истории сессии.

## 4. Доставка

**Delivery-gate (B3, обязателен до билда):** юнит-тест рендерит `build_system_prompt("ru")` и `build_system_prompt("en")` и проверяет, что каждое имя искажения, встречающееся в few-shot блоке, принадлежит соответствующему каноническому кортежу (`DISTORTIONS` / `DISTORTIONS_EN`). Защита от молчаливого регресса: криво переведённое EN-имя канонический фильтр в `groq_client` выкинет в пусто (только WARN). `pytest` должен быть зелёным до сборки образа.

Стандартный GitOps-цикл ([[backend-deployment]]), в два захода (таймаут сборки):
1. rsync `cbt-backend/` на registry-LXC → `docker build/push localhost:5000/cbt-backend:v0.1.9` → `sed` тег в `cbt-backend/k8s/deployment.yaml`.
2. `git commit && git push` в Gitea → `kubectl -n argocd annotate app cbt-backend argocd.argoproj.io/refresh=hard --overwrite`.

Ноль изменений в iOS / web. Промпт правится без передеплоя клиента.

## 5. Проверка (smoke, до/после на фиксированном наборе)

| Вход | Ожидание |
|---|---|
| `усталость` | `[]` (был баг `Катастрофизация`) — регресс |
| `мне тревожно перед собеседованием` | `[]` |
| `мало готовился, могу плохо сдать — позанимаюсь` | `[]` (соразмерное) |
| `я завалил собеседование, меня теперь никуда не возьмут` | непустой; `explanation` **содержит цитату** из фразы |
| то же с `"language":"en"` | `name ∈ DISTORTIONS_EN`; `explanation` английский с цитатой |
| 2–3 реальных спорных кейса от пользователя | оценивается вручную после деплоя |

**Критерий успеха (ручная оценка до/после):** на не-мыслях — пустой массив; на реальных мыслях `explanation` цитирует конкретную фразу и объясняет механику, а не общую формулу.

## 6. Риск и откат

- **Риск:** перекос набора может сместить распределение детекций. Снижается равномерным покрытием всех 18 + сильным блоком из 5 негативных примеров.
- **Откат:** одна строка — вернуть тег образа `v0.1.8` в `deployment.yaml`, ArgoCD синкнет за минуту. Промпт — единственное изменение, риск изолирован.

## 7. Out of scope

- Поле `quote` в JSON / двухшаговый вызов (подход C) — отклонено, ломает контракт.
- Автоматический eval-набор / метрики precision-recall — возможный v2, сейчас оценка ручная.
- Изменение списка `DISTORTIONS` на нейтральные коды — отдельная большая работа, не здесь.
